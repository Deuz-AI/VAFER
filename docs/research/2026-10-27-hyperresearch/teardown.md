# hyperresearch teardown (v0.12.0, commit 327498b)

Date: 2026-10-28. Inputs: the reader notes, verification passes and three critiques in this folder, and the clone at `C:/Users/VECTOR/Documents/GitHub/hyperresearch`. Paths are under `src/hyperresearch/`. "Verified" means an independent check against the code; "estimate" means derived from reading prompts. Nobody on our side has run the pipeline end to end, or vafer-research 0.1 on Claude Code.

## 1. What hyperresearch is

A long prompt pipeline on a small Python CLI (`hpr`), installed into a project.

- **Entry.** `hyperresearch install .` writes a CLAUDE.md block (~3–4K tokens, always loaded), 18 step skills, 16 agents and a PreToolUse hook (per-project Claude Code installs), or AGENTS.md, step files, 15 TOML agents and a Stop hook (Codex). A router skill loads one step skill at a time and ends with `run finish`.
- **Tiers.** "Default is `full`. When uncertain, tier up" (1-decompose.md:117). light = steps 1, 2, 10, 15, 16, 15–25 sources, ~30–40 min; full = steps 1–16 plus 14.5, 55–80 sources, ~1.5–2.5 h; premier = 100–130 sources, ~3–5 h.
- **Steps (full).** 1 decompose: atomic items, H2 headings, period-pinned filings, a coverage matrix. 2 width sweep: the lead runs 40–100 searches and scores 80–120 URLs; 10–12 Sonnet fetchers (then 3–5, then 2–3) fetch URL batches, write summaries and 3–25 quoted claims, and chase 3–8 primaries; coverage checks launch waves 2–3, then claims ingest, independence audit and PageRank. 3–9 contradiction graph, two loci analysts, up to six investigators with committed positions (who must spawn their own fetchers), source tensions, a filing check and corpus critic with 2–4 gap fetchers, a claims digest. 10–16 the writing chain: three Opus drafters (each told to read 20–50 notes), a fresh synthesizer, four critics, gap fetch, a patcher, cite-check (Python pairs sentences with cited notes, a triage auto-passes some, a Sonnet checker judges the remaining numbered pairs or 60% of weak wikilink pairs), polish, readability.
- **Subagents.** 16 roles; 35–60 spawns per full run (estimate); Sonnet fetches, analyses and cite-checks (at most six source analysts for long sources), Opus writes.
- **Enforcement.** Code decides only the ship gate `run finish`: a length band, required headings as substrings, ≥9 citations per 1,000 words, quote-integrity, retracted citations (wikilink style only), existence of critic, patch and polish artifacts, and a parsed cite-check findings file when the manifest marks 14.5 done. Claude Code adds tool allowlists and a reminder hook that always exits 0; Codex adds a Stop hook that blocks once. Step order, source minimums, coverage and the budget are prose.
- **Vault.** Markdown notes plus SQLite (FTS5, links, claims, sources, escalation queue); every CLI call rescans and syncs; corpus queries are scoped to a per-run tag; embeddings, dedup, topic tree, index pages, MCP server and web viewer exist unused (verified).
- **Acquisition.** Agents search with the host's WebSearch; Python fetches: a fresh headless Chromium per URL, a PDF lane, SSRF, login-wall and junk gates, open-access rescue (Europe PMC only by default), seven scholarly APIs (four keyless; named only in CLAUDE.md), and a Claude-in-Chrome lane (Claude Code only).
- **Verification.** Claims table, cite-check, quote-integrity, retraction scan, independence clustering, an `<untrusted-source>` fence on two CLI read paths (not MCP), PageRank plus a quality composite.

## 2. What drives quality, and what is ceremony

Nothing in the repo isolates any component: no ablation, one sample report (58.3 RACE on one DRB query), and the only triple-draft "evidence" compares two questions, one run each (hyperresearch.md:313).

**Plausible drivers**

1. **Breadth with full-text reading by subagents.** 55–80 sources, each a fetcher is told to read whole before summarizing, quoting claims and chasing primaries; on Claude Code, Bash output is cut near 30K characters, so long sources are read from the start unless one of at most six source analysts takes them (verified). The sample cites 97 sources, 87 on arXiv.
2. **Per-source curated notes**, so drafters, critics and the cite-checker re-read sources without the lead holding them.
3. **Pre-draft adversarial work and committed positions**: designed, partly delivered. Investigators must commit to a position with confidence, boundaries and falsifiers, and the corpus critic asks "what source would overturn this?" before drafting. But step 4 drops the seed evidence and opposing positions before step 5, step 8 counts a failed counter-search as added confidence, and step 7's promised "Source Tensions" subsections have no consumer (verified).
4. **A fresh single writer with concrete prose rules**, a plan and an outline: where the prose is made, though its source-checked conflict verdicts never reach the synthesizer's prompt (verified).
5. **The LLM cite-checker plus patcher**: the only mechanism that reads the cited source against the sentence. Undermined; see §3.
6. **Quote-integrity in the gate**: the only mechanical content check that blocks.
7. **The instruction critic** (named entities, sub-questions and format cues of the verbatim question), which the authors call the widest-variance dimension.
8. **Engineering for compaction** (one step skill at a time, state on disk). V7's single 1,200-line skill got evicted and the orchestrator "silently dropped" the corpus critic and triple draft "in 100% of runs where the orchestrator didn't re-read the skill file" (hyperresearch.md:309; a V7-era self-report, no run count).
9. **What the vendor's current path keeps.** Hosted "Deep" now runs chaptered research, an evidence map from every kept source, a section-brief plan, one one-pass writer and a figure-level claim check; the OSS writing chain is its fallback (how-it-works page; partly verified: only 3 of the 10 DRACO reports are credited to this writer, and the page is inconsistent on whether "steps 1 to 11" includes the triple draft). Revealed preference, not the scored design.

**Ceremony or pure cost**

- Triple draft plus synthesizer: three full Opus drafts, unmeasured, replaced in the vendor's current design.
- Inline utility scoring of 80–120 URLs in the lead's context; it also gates the browser-lane queue and feeds the quality composite.
- PageRank and the quality composite: applied after the SQL LIMIT, so only the top 20 are reordered, and the provenance edge points the wrong way, from the primary to its suggester (verified); retraction (×0.55) is the one strong lever.
- Independence scores: a k-copy cluster scores 1+(k−1)/k, so two syndicated stories can reach the "3.0 consensus" bar; no code sums the scores (verified).
- Mechanical cite-check triage: removes pairs from the only real check while auto-passing wrong numbers (§3).
- Dead or unused: the USD budget, count ceilings, cost telemetry, stall detection, lifecycle and `repair`, embeddings, MCP, viewer, topic tree.
- Always-on footprint: ~7K tokens of CLAUDE.md and skill listings in every session of the project.

## 3. Costs and weaknesses

**Latency.** light ~30–40 min, full ~1.5–2.5 h, premier ~3–5 h (profiles.py:306-373).

**Tokens and money.** One user estimated a v0.10.0 full run at about 8.6× a $25 ceiling (~$215) while the manifest recorded $0 (#92). Estimates: fetchers are told to read 100–150 pages whole (≤1.5M input tokens before host truncation); `search --json` returns up to 20 full bodies, uncapped.

**Tool calls.** 4–5 CLI processes per URL, each rescanning the vault; 70–200 searches per run against Claude Code's 200 per session; 35–60 spawns.

**Complexity.** `core/hooks.py` is 4,545 lines; agent prompts ~163K characters; ~1,200 unit tests cover Python, none what the model does. Shipped and never worked: the reminder hook, the claims table (empty until 0.11.1), stealth, a builtin provider with no PDF lane.

**Brittleness** (verified against code unless noted).
- Prose-only gates get skipped: "the conditionals only hold when a skill forces a written verdict" (#38); premier run Q62 never invoked `run verify`. Its other symptoms are confounded: the 25,647 words against a 16K ceiling came from a hardcoded word table (61e77cc), and the 24 quote flags dismissed as "false positives" came from a regex that turned "38 legitimate short quotes into 42 false errors" (CHANGELOG.md:20).
- The gate checks that artifacts exist, and the orchestrator pre-stubs the patch, polish and cite-check patch logs, so critical cite-check findings count as resolved once a `[]` log exists; nothing requires any step to have run, `light` drops the critic checks, and resume and the Codex Stop hook skip cite-check, which is not a profile step.
- The triage auto-passes on number substrings, citation markers included: "grew 5%" passes against a 25% claim, "[12]" against "2012"; 125 of 155 mock-vault pairs carry an own index of 10 or more, which enters the test. It judges against fetcher-written `quoted_support` nothing compares with the page. Unlisted numbered citations vanish silently, and a non-standard heading (`## Kaynaklar`) yields zero pairs and a passing gate.
- Quote-integrity accepts any 5+-word double-quoted span found in any note, LLM-written ones included; the lint allows dropping the quotation marks, and no code can tell a fabricated quote from a rhetorical one.
- Polish hedge-stripping (register-dependent) and the router's compression rewrite after a failed gate change claims after cite-check; only verbatim quotes are re-checked.
- No Stop hook on Claude Code: one headless run needed 13 invocations, five exiting 0 mid-pipeline (PR #163).
- The login-wall gate flags any title containing "auth", "register", "sso" or "sign in", so every Federal Register, EBA and AEA page is rejected with "do not retry" after an OA rescue attempt; on Claude Code a browser lane capped at 25 per run may recover a few, on Codex they are lost.
- SQLite: 6,000 unresolved links made 5 of 6 parallel `note update` calls die with "database is locked", most losing the update; reads fail too (synthetic load).
- No corpus reuse: each run mints a fresh tag and already-fetched URLs are skipped, never re-tagged, so an overlapping re-run omits the earlier sources and probably refetches to compensate (unmeasured); default reports carry no frontmatter and are not indexed; only the untagged reminder hook and `claims search` read the whole vault.
- The sample report ships 38 of 97 bibliography titles broken, "corpus" 16 times in reader prose, and a derived "55% relative improvement" that is 56.7%; no gate checks derived arithmetic or the Sources list.

**Hosts.** Claude Code gets real tool allowlists, a browser lane (unverified), the reminder hook (per-project installs only) and no completion control; whether its subagents can spawn step 5's fetchers is open (docs allow nesting; our subagent sessions lacked an Agent tool). Codex gets a soft Stop hook (blocks once; off under default `codex exec`), no tool locks, no nested subagents, no browser lane, no benchmark. Windows: the installer overwrites a project `.claude/settings.json` that fails to parse (a BOM suffices; any OS); the unquoted CLI path in agent prompts breaks on a space in the user name; 22 Codex commands carry a POSIX env-prefix that PowerShell rejects.

**What DRACO #1 shows.** The board measures "Hyperresearch Deep (hosted), Oct 2026", chaptered research; only 3 of HR's 10 reports are credited to the current Deep writer, the other 7 unstated. README.md:25 "the same pipeline" is contradicted by the vendor's own page. The vendor chose the ten tasks, ran each system once, graded with GPT-5.2 rather than Gemini-3-Pro, and ran it itself. Other comparators were handled unevenly; Claude Research was run and graded like HR. Against Claude Research the split is 5–5; Medicine (72.2 vs 37.1) supplies 75% of the 4.67-point gap, beyond the page's ~9-point re-grade spread and, where penalties reach −500, most likely a safety penalty (inference); without it the gap is 1.29 and an exact sign-flip test gives p ≈ 0.31. Net: hosted Deep is roughly level with Claude Research on ten easier-than-average tasks; DRACO says little about the research steps and nothing about the OSS writing chain, Codex or statistical superiority.

## 5. Opportunities

Time and cost are not VAFER axes: bare Codex also beats HR on both, and our Standard runs were 1.5–2× slower than bare; report both as ratios to bare, with Standard ≤1.5× bare as the bar. On Claude Code the comparator is the bundled `/deep-research`, which votes on each claim and lists the unchecked ones (spec arm D); if it wins one-off reports there, VAFER's case rests on reuse, follow-ups and Codex. Against the bare model expect 0–5 points, more on enumeration (a wide-table variant, spec M5), post-cutoff and Turkish-local tasks. So 5× is claimed only on rates, reported with the count of supported claims, since fewer claims is gaming (spec §6): unsupported load-bearing claims per report, searches and minutes per follow-up on an INDEX hit, and run-to-run spread in checklist coverage.

1. **Verify at capture, check at write (M2 `check`).** On Claude Code the brief tells researchers to ask WebFetch for the exact sentence or NOT FOUND (curl when allowed); on Codex they copy from the line window; each note quote is marked verified or unverified. A stdlib script (no network) then checks every quoted span and source figure in the report against the notes entry for the same cited URL, and flags uncited numbers (HR checks neither). Numbers are normalized (decimal comma, separators, %, units); a figure marked derived shows its inputs [n] and operation and is recomputed; table cells carry header, unit and period. The check is advisory and logs every verdict with a one-line disposition per flag; it binds only after a logged audit shows ≥80% precision, and the remedy is fix or mark unverified, never delete. Home: a brief line, a SKILL.md clause, the script. Evidence: fact-check accuracy fell 79→17% (GPT-5.4) and 80→58% (Opus 4.6) from 2 to 150 calls; the gain is unmeasured. 5×: candidate on unsupported load-bearing claims if the baseline is already low. On Codex (no shell network) the script sees notes only; item 2 reads pages there.
2. **Fresh-context verifier** that reads the cited page, for triggered claims only (≤8): supported, partial with the exact fix, unsupported, wrong-source; any number, unit, date or magnitude mismatch is critical; nothing edits the report afterwards. On Codex it is the only page-level check. Cost: 1–2 spawns, one brief. Evidence: PANINI +16 (gpt-oss, short answers); the Opus 5 guide warns against verify subagents, so ablate per model family first. 5×: no (+0–10 points of support rate).
3. **Citation hygiene lint.** Every `[n]` resolves to an opened URL, every listed source is cited, every entry has a real title (not a PDF header or arXiv stamp), URLs are normalized, the report carries no internal labels (`[GAP]`, `[prior]`, row statuses, "researcher", "wave"), and uncited general knowledge is marked inference. Cost: trivial. 5×: no known baseline; a lint, not a claim.
4. **Reuse that pulls instead of skips.** Write the INDEX line at plan time with a status and update it at delivery (a local run died mid-wave with no INDEX line). On a match, reuse saved quotes marked "reused from <run>, opened <date>, verified or unverified", re-open volatile entries, and reuse dead ends (NOT-FOUND queries, blocked URLs). Cost: ~30 words. Evidence: files plus agent 72.5% vs RAG 48.5% on LongMemEval-V2 (QA over trajectories). 5×: candidate on searches and minutes per follow-up on an INDEX hit; claim the spec's 30% until the two-session test.
5. **Time, reported against bare.** Log per-phase timing from file times; target Standard ≤1.5× bare; aim the gap wave at the 1–3 open rows with the highest decision impact × uncertainty. Interim headlines travel only in the message that launches the gap wave, marked preliminary, never in headless runs, since a text-only message ends the turn (PR #163); the on-disk draft is the insurance. Cost: one SKILL.md line. 5×: no.
6. **Floors against run-to-run variance.** First diagnose: compare the Codex runs' plan.md files and method notes. Then tier floors, not per-row prose: Standard always runs one gap wave unless every row is COVERED; spawn researchers when the plan has 3+ groups; a COVERED row needs only a URL; a NOT-FOUND row records the queries, search mode and any tool error, rate limit or blocked page. The gap-finder also returns the verbatim question's named entities, places, periods and format cues as items for plan rows. On Codex, test the search mode up front on recent topics (a dated query); if cached, say so and suggest `--search`. Evidence: v0.0.3 pasted one rationale into every row. Cost: ~60 words. 5×: candidate on spread in checklist coverage, unmeasured.
7. **Rule 5 gains, with a named consumer.** A figure for a named period comes from that period's record; for judgments and forecasts, one search per headline conclusion for the strongest counter-evidence, a miss recorded with its queries and leaving confidence unchanged; no chase quota, but each key number is marked "primary" or "secondary only (reason)". Each CONFLICT row gets a verdict (which side, why), shown in "Where sources disagree". No numeric confidence bands: nothing consumes them. Evidence: our aggregator exchange rate (efccf1b). Cost: ~50 words. 5×: no.
8. **Writing rules that are not benchmark tricks** (~50 words): say each idea and piece of evidence once; choose which sources to cite for a point, never which points to make; a table when 3+ entities are compared on 2+ dimensions; scope a claim by its counter-evidence instead of appending caveats; for medical, legal, financial or safety questions, state scope, conditions and contraindications next to any recommendation, never a dangerous or jurisdiction-wrong instruction as advice. RACE-tuned rules (primers, citation targets) stay out. Evidence: DRACO's −500 medicine penalties sit under the board's largest swing. 5×: no.
9. **Local-language coverage made explicit** in briefs.md: one scout query per language where the best sources live, name variants, the national record types (gazette, regulator tariff tables, council decisions). HR's `## Kaynaklar` failure is in §3. Evidence: none yet; test with a Turkish-local question with an answer key (item 11). 5×: no.
10. **Hold or do not import.** Hold until a side-by-side shows a gain: a chase quota, confidence bands, keyless OA and retraction lookups (curl is blocked under Codex workspace-write). Do not import triple drafts, four critics, a shared SQLite vault, PageRank or source scores, independence weights, tool locks, hooks, utility scoring, length-band gates, or an always-on block: each is unmeasured, host-specific or shown inverted above. Effect: unmeasured; item 6 keeps the instruction critic's checklist.
11. **A side-by-side that can run.** Compare within a host, each arm in a clean folder outside git. Claude Code: vafer-research, bare, `/deep-research` and HR light on three questions (Turkish-local with an answer key, post-cutoff, enumeration), HR full on one. Codex: vafer-research and bare. Run VAFER and bare twice each; name the HR tier in every comparison. Score every report alike: ten headline claims checked by hand against the cited page, plus minutes per phase, searches and spawns. Cost: about two days (HR light 30–40 min, full 1.5–2.5 h per run). Samples this small show time gaps only; quality needs item 1's audit.
